# Decisions

Deviations from `docs/PLAN.md` and the reason for each. Newest last.

| Date | PLAN reference | Deviation | Reason |
|---|---|---|---|
| 2026-11-25 | §25 M0, "deployed skeleton on the VPS" | M0 is verified in a local browser. No VPS, Docker Compose or Caddy config is built yet | No host has been chosen (PLAN §27 open item 4), deploys to a public host need Andy's go-ahead, and Docker is not installed on the build machine, so a compose file could not be tested. It is built when a host exists |
| 2026-11-25 | §19 repository layout | Packages are added when they get real content | Empty placeholder packages add noise and drift |
| 2026-11-25 | §16 sprite source format example | `anim` takes `{ frames, fps }` per animation instead of one shared `fps` | Animations of one sprite run at different speeds (idle 3, hop 10, death 12) |
| 2026-11-25 | §16 characters, "hair and jacket colors use a palette lookup shader" | Slot pixels are written as reserved key colours and swapped when the client composites a look; hands are drawn in the sleeve pieces with the skin slot | Layers composite back to front, so a hand drawn in the body layer would be hidden by the uniform; key colours keep any recolouring method open for the client |
| 2026-11-25 | §16 outline rule | Outline pixels must be the darkest step of a ramp the sprite uses; the ground shadow layer and `lone` characters (eyes, sparkles, debris) skip the outline and orphan checks | A 1 px dark sole or pupil is correct pixel art and would otherwise fail |
| 2026-11-25 | §6 view, "×2 on phones in landscape" | The integer scale is counted in device pixels, not CSS pixels: an 844×390 phone at device pixel ratio 3 draws each game pixel as 4×4 device pixels | A whole CSS multiple does not fit a phone's CSS viewport above ×1, and a whole device-pixel multiple is what keeps pixels crisp at any ratio |
| 2026-11-25 | §16 "soft blob shadows under everything" | The client draws a rig's `shadow` layer as its own sprite at 35% opacity under every entity. A sprite gets its own shadow by adding a frame named `shadow`; until then it borrows the default student look's blob | The 오답 art has no shadow yet and the sprite sources are being redrawn, so the client takes the shadow from names in the metadata instead of a hand-written fallback |
| 2026-11-25 | §16 palette themes, "each Page gets a palette theme" | Campus also has time-of-day and light themes: `campus-night`, `field-night`, light bands `campus-lamp`, `campus-dusk`, `campus-glow`, and rift bands `rift-sun`, `rift-warm`, `rift-ember`, baked like era themes | No lighting engine exists yet; night, lamp pools and rift glow are painted as palette swaps so scenes can be judged now. Phaser lighting (§16 "Where the wow comes from") can replace them later |
| 2026-11-25 | §16 tiles, "2 to 4 variants per base tile" | Terrains also take tone overlays (soft patches larger than a tile, picked by low-frequency noise) and several outer/inner pictures per pair | One picture per pair repeats its edge every 16 px and a hashed variant per tile cannot vary at a scale larger than a tile; both read as a grid |
| 2026-11-25 | §16 outline rule | Modular pieces that join edge to edge (facade, fence, sea wall) and shadow-only or backdrop sprites turn the outline check off and draw their outer outline by hand | The rule treats the frame edge as transparency, which would force an outline at every join |
| 2026-11-25 | §16 "Soft blob shadows under everything" | Props declare their ground shadow as a `shadow` grid, compiled to the `shadow` frame the client already looks for; on the contact sheet, scenes darken the ground under it one ramp step instead of drawing it | One shape serves both: the client draws it translucent, the palette-locked sheet draws it as a ramp step |
| 2026-11-25 | §16 "Reviewing art without an artist" | The contact sheet also renders scenes: one 480×270 screen built from the atlases, with backdrop, terrain, details, edges, shadows, sorted objects, overhead, lights and atmosphere layers | Art is judged in composition; the layered scene description is kept small as a seed for the map format |
| 2026-11-25 | §6 view, §16 spec "Player character 16×24" | The student rig's frame is 24×26 with the body in the centre 16×24, feet at row 24 | The book strike and the knocked-out pose reach past the body, and tall hairstyles stay inside the frame when the head bobs up a pixel. Atlas frames are trimmed, so the larger canvas costs nothing |
| 2026-11-25 | §16 frames "idle 2, walk 4, attack 4, hit 1, knocked out 1" | The student rig adds two fidgets that play now and then: a stretch with a yawn and a page turn | The owner asked for player characters with life in them; the 2-frame idle stays the base loop |
| 2026-11-25 | §16 sprite source format | A rig pose can carry its own position (`{ at, grid }`), and pose grids of one piece may differ in width | A raised arm, a strike or a body lying down sits somewhere else than the resting piece; copying offsets into every frame would be worse |
| 2026-11-25 | §16 frames, knocked out | The knocked-out frame is every part's side view transposed, so the body lies face down with light still from the top left, the same from every direction | Every hairstyle, face and garment falls over with no extra drawing, and the pose reads as flat out at ×1 |
| 2026-11-25 | §16 characters | Dialogue portraits use a clay and rose skin ramp instead of the skin ramp | The skin swap slot shares the name `skin`, so the palette's skin ramp cannot be named from a legend; portraits are fixed characters and do not need the slot |
| 2026-11-25 | §16 outline rule | UI pieces that are only ever drawn onto another piece (ruled lines, tab and name-tab bottoms, the speech-bubble tail, bar fills, the red-pen selection loop, the margin line, the empty slot cell, touch glyphs) set `outline: false`; pen strokes and cover symbols are `lone` | They are ink on a surface, not silhouettes against the field; an outline would draw a border exactly where the pieces are meant to merge |
| 2026-11-25 | §18 "Korean font … bundled" | Text is drawn from BMFont atlases built from Galmuri's BDF faces (Galmuri11, Galmuri11 Bold, Galmuri9) rather than from the web font | Canvas text with a pixel font is never crisp (engine-notes §10). Each face is a 1-bit PNG of about 25 kB plus about 1 MB of XML metrics (64 kB gzipped), so the host must serve the XML compressed to keep the first load under 5 MB |
| 2026-11-25 | §16 palette, 해솔 64 as hue-shifted ramps | Revision 2 merges four near-identical colours into the ramp step they sat next to, keeping the old names as aliases (`ink.light` #706f8a → `stone.dark` #6a6276, `skin.deep` #4b2629 → `wood.dark` #4f2d26, `skin.dark` #773f35 → `clay.dark` #7a3329, `grass.dark` #23533a → `board.mid` #336555), and spends the four slots on named steps outside the ramp order: `grass.soft` #53923f, `stone.lamp` #d5c3a0, `stone.vein` #a89a8c, `clay.dust` #e8a768. The fixed skin ramp is named `flesh`, so `skin` in a legend always means the swap slot | The palette had no lawn green between mid and light, no grey for lamp-lit stone, no warm marble shadow and no sunlit dust, so lawns read as dots, lamp pools as brown dirt and Greek ground as orange. The merged pairs were under 10 ΔE apart; extras stay out of the step order so shadows, outlines and ramp remaps never shift |
| 2026-11-25 | §16 "Reviewing art without an artist", build checks | A rig's checks also run on probe looks: every part option worn on the first look in place of its own, in every direction and frame | The character creator combines parts freely, so checking only the hand-picked looks left most hairstyle, face, garment and accessory combinations unchecked |
| 2026-11-25 | §16 outline rule | In garments the sleeve and trouser marks are `lone`, so a one-pixel forearm or shin may stand alone in a pose | The owner asked for full motion (the hit flail, the strike, the yawn) instead of poses simplified to satisfy the orphan check; every other pixel of a garment is still checked |
| 2026-11-25 | §2 decision 30 "No day cycle" | Each map has one fixed time of day and weather of its own, part of its identity: `campus-yard` stopped at 16:50 in golden light, `campus-field` at 23:40 at night. A map declares its clock, phase, weather, ambient colour and strength, and its light sources | Time tore, so the clock stopped differently in each place. A fixed light per map gives every map its own mood and needs no day-cycle system |
| 2026-11-25 | §16 "Maps are authored as code … Output is tilemap JSON" | A map builds to its own JSON (`packages/art/dist/maps/<id>.json`): terrain as one legend character per cell plus a seed, art placed by atlas name in named depth layers, collision, spawns, portals, interactables and zones. Not a tile-index tilemap | Tile indices change with every art build; names and a seed let the client pick dual-grid tiles itself, and one file serves the client, the server and the contact sheet |
| 2026-11-25 | §19 repository layout, `shared` and `content` imported by both sides | The layered scene format moved from `art` into `content` (`maps/layers.ts`). `art` depends on `content`: its renderer uses the types, and `art:build` builds, checks and writes the maps | Maps and review scenes share one format. The map checks need the art metadata, and `art:build` already writes every static file the client loads |
| 2026-11-25 | §6 Physics "Tile collision grid per map" | Collision is stored as rows of characters (`.` walk, `#` solid, `~` water or void) and read through `isSolidTile(map, tx, ty)` in `shared`; tiles outside the map are solid | Readable in the JSON and in diffs, cheap to index, and the simulation in `shared` can read it without importing `content` |
| 2026-11-25 | §16 sprite source format | Prop footprints are declared in `content` (`PROPS`, by sprite name), not on the art source | Collision is a game rule; the art package stays free of rules |
| 2026-11-25 | §16 tiles, "a generator per map type lays terrain with noise" | `content` has its own seeded noise for map rules instead of importing the tile picker's hash from `art` | The contact sheet page runs `art` sources in the browser without a bundler, so they import nothing from `content` at runtime, and `content` cannot depend on `art` without a package cycle |
| 2026-11-25 | §16 palette themes (time-of-day themes row above) | Golden hour themes `campus-golden`, `golden-sun`, `golden-warm` and `golden-shade`; a scene or map may name a `shade` theme that paints its ground shadows instead of one ramp step | Under a low sun a one-step shadow read as dirt; cool violet and teal shade against warm ground reads as late afternoon |
| 2026-11-25 | §16 palette themes, rift bands | `rift-sun`, `rift-warm` and `rift-ember` now turn lawn olive and dim instead of leaving it daylight green, which also changes the grass at the edges of the `agora-rift` scene | Daylight-green lawn under a night sky read as a hole in the night rather than as the era's light falling on it |
| 2026-11-25 | §10 Maps, §26 testing | The `lawn` map keeps its old shape with an added all-walkable collision grid, outside the map format and the map checks | Player movement is being built on it right now; it is replaced by real maps once movement reads built maps |
